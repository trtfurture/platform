# SCHOOLS — Schools.co.ke

**A Toror Technology and Innovations Limited product.**

SCHOOLS is a Kenya-first education discovery and institution marketing platform. It brings schools, colleges, TVET institutions and universities into one directory, while providing paid promotion options, school website/portal enquiries and a campus-living marketplace.

## What is included in this first deployable release

### Public website
- Responsive homepage with a softly blurred campus hero image and combined search.
- Private schools, public schools, colleges/TVET institutions and universities entry points.
- Directory search by keyword, institution type, county, ownership, level, accommodation, gender, town and curriculum/programme.
- Institution profile pages with basic details, photos, a video link, external website and enquiry form.
- County/category landing routes and a dynamic XML sitemap.
- School advertising submission form with multi-photo upload and preferred promotion tier.
- School website/portal interest form.
- Student accommodation / campus-living marketplace submission and moderation.
- About and launch-draft privacy pages.

### Recognition and promotion rules
The site deliberately treats identity/verification and paid promotion as separate fields:

| Display | Meaning | How it is assigned |
|---|---|---|
| White — Recognised listing | A basic public-information listing for a known institution. It is not a claim that the institution has confirmed the page. | Seeded by the platform administrator after public-source review. |
| Brown — Institution confirmed | The institution's authorised representative has been checked and the profile confirmed. | Admin-only trust-status change after evidence/review. |
| Green — VIP · Sponsored | Paid boosted placement, ordered above ordinary listings within matching results. | Admin activates after payment is confirmed. |
| Gold — VVIP · Sponsored | Higher-priority paid placement, plus rotating cross-platform visibility on relevant pages. | Admin activates after payment is confirmed. |

VIP and VVIP promotions can be assigned for 30, 60 or 90 days. When the promotion expires, the paid badge and paid ranking automatically stop. Promotion never changes verification status. Sponsored placements are labelled.

### Admin
- Admin username and password are read from `ADMIN_USERNAME` and `ADMIN_PASSWORD` environment variables.
- Production refuses to start if those values and a 32-character-or-longer `SESSION_SECRET` are missing.
- Admin sign-in is rate limited; password comparison uses bcrypt; sessions are stored in SQLite (not Express's in-memory development store); admin changes use CSRF tokens.
- Review and publish institution listings, renew posted listings for 30 days, set recognition/confirmation status, activate promotions, moderate campus rental listings and view parent/portal enquiries.
- Application exceptions are recorded in the admin error log.
- SQLite backups are created at startup and daily, with a rolling set retained on the persistent disk. Admin can download a current SQLite backup from the dashboard.

### PWA
- Web app manifest, Android-sized icons, service worker and offline fallback page are included.
- The service worker caches the app shell only; live search, admin pages, uploads and current institution details require a connection.

## Run locally

Requirements: Node.js 22.x and npm.

```bash
npm install
cp .env.example .env
# Edit .env and choose a unique local ADMIN_USERNAME, ADMIN_PASSWORD and SESSION_SECRET.
npm run check
npm start
```

Open `http://localhost:3000`.

Local development can use the fallback admin login `admin` / `admin12345` only when `NODE_ENV` is not `production` and no `ADMIN_PASSWORD` is supplied. Prefer setting local environment values in `.env`; never use the development fallback on a public server.

Admin URL: `/admin/login`.

## Render deployment

A `render.yaml` Blueprint is included.

1. Push the contents of this folder to a new GitHub repository.
2. In Render, choose **New → Blueprint**, connect the repository and apply the Blueprint.
3. Render creates a Node web service and a persistent disk mounted at `/var/data`.
4. During Blueprint setup, provide a unique `ADMIN_USERNAME` and a strong `ADMIN_PASSWORD` when Render prompts for the two `sync: false` environment variables. `SESSION_SECRET` is generated by the Blueprint.
5. Confirm `PUBLIC_SITE_URL` is `https://schools.co.ke` after the domain has been attached. `SIGNATURE_QR_URL` controls the destination of the footer QR; it defaults to the site home page.
6. Add `schools.co.ke` and (optionally) `www.schools.co.ke` in Render's Custom Domains screen. Copy the exact DNS records Render displays into the domain registrar's DNS manager. Do not guess the A/CNAME targets; use the values shown by Render for this service.
7. Wait for the deployment health check at `/healthz` to pass, then test the homepage, directory, image submission, admin login and backup download.

**Important:** Keep the Render service on a plan that supports the included persistent disk. SQLite, uploaded images, backups and admin sessions are stored under `/var/data`. Do not deploy multiple web instances against the same SQLite file.

## Environment variables

| Variable | Required in production | Purpose |
|---|---:|---|
| `NODE_ENV` | Yes | Set to `production`. |
| `PORT` | Supplied by Render | HTTP port. |
| `PUBLIC_SITE_URL` | Yes | Canonical public URL, e.g. `https://schools.co.ke`. |
| `DATA_DIR` | Yes | Set to `/var/data` on Render. |
| `ADMIN_USERNAME` | Yes | The one administrator's login name. |
| `ADMIN_PASSWORD` | Yes | The one administrator's password; never commit it. |
| `SESSION_SECRET` | Yes | Long random secret, at least 32 characters. Render generates it in the Blueprint. |
| `SIGNATURE_QR_URL` | No | QR destination. Defaults to the public site's home page with a source tag. |

## Seed listings

The initial database seeds a small set of well-known institutions (Alliance High School, Strathmore School, University of Nairobi, Kenyatta University and Kenya Utalii College) as white **Recognised listing** entries. They are not paid placements and are not represented as directly verified by those institutions. Their public profiles use official website links as the primary reference. School staff can request a claim/confirmation through the advertising form.

Do not bulk-import scraped student data, private contact details or student images. Keep information limited to appropriate institutional/public details, and verify changes with the institution.

## Launch limitations — do not mistake these for completed features

This is the first operational MVP, not the full future platform. These items require a subsequent build or third-party credentials:

- **Live M-Pesa checkout / automatic renewals:** not connected yet. Promotion/payment must be confirmed out-of-band by the administrator before applying VIP/VVIP. Do not activate a paid tier based only on a request.
- **School-owner self-service account:** not included yet. For now, institution owners submit a profile and the administrator updates, renews and manages promotion.
- **Full school-management portal:** the site currently collects portal-development requests; it does not yet provision a separate school website or provide student/parent/teacher logins, fees, attendance or marks.
- **Video hosting/transcoding:** profiles accept an external video URL; the platform does not yet host or transcode large video files.
- **Automated email/SMS notifications:** not connected. Enquiries are visible in the admin dashboard.
- **Legal review:** the privacy page is a launch draft. Complete it for the actual data flows and obtain appropriate legal review before collecting substantial personal data.
- **Production monitoring and off-site backups:** local rolling backups and admin downloads are included. Configure a separate off-site backup destination before relying on the service for important production data.

- `/schools` — all-institution search

- `/school-portal` — request a school website/portal
- `/campus-living` — student rentals and accommodation
- `/admin/login` — admin sign-in
- `/admin` — protected admin dashboard
- `/sitemap.xml` — XML sitemap
- `/robots.txt` — crawler instructions
